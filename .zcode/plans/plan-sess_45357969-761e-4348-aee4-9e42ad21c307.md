# 新增"剪映缓存和日志数据清除"工具栏按钮及功能

## Context

DiskSeek 工具栏已有 智能清理C盘 / 清除重复文件 / 微信迁移 / WPS迁移 四个按功能入口，均为"工具栏按钮 → 专用对话框 → 独立引擎"模式。剪映专业版（JianYing Pro）的缓存与日志（本机实测 `Log` 单目录达 6.4 GB，素材缓存可达数十 GB）常驻 C 盘，且应用内"清理缓存"不彻底。本次新增第五个按钮：扫描剪映的缓存/日志/临时目录并逐文件清理，**不触碰草稿、预设、配置等用户数据**。

## 清理目标白名单（本机实测验证）

清理（内容清空，保留目录本身，应用重启自动重建）：
- `%LOCALAPPDATA%\JianyingPro\User Data\` 下的 `Log`、`VELog`、`EMaterial`、`CEF`、`Crash`、`ExceptionMonitor`、`LVOPTmp`、`Tracking`、`TTNet`、`bach_private_cache`
- `%LOCALAPPDATA%\JianyingPro\bach_private_cache`
- CapCut 国际版（剪映海外版）同名镜像路径（`%LOCALAPPDATA%\CapCut\...`），不存在则自动跳过

绝不触碰（白名单机制天然隔离）：`Projects`（草稿）、`Presets`、`Cloud files`、`Config`、`MMKV`、`SettingsSDK`、`Download`、`VideoRecord`、`Apps`。删除时逐文件再次过 `SmartClean::IsDeleteBlocked` 门 + 展开后路径前缀校验。

## 文件改动

### 新增引擎 `windirstat/JianYingClean.h` + `JianYingClean.cpp`（namespace JianYingClean）
- 上述白名单路径表 `constexpr std::array`（每条带类型键 `IDS_JIANYING_TYPE_CACHE/LOG/TEMP`）
- `ScanState { vector<TargetResult{path,typeId,size,count}>, atomics }`、`CleanState`（atomic 计数，与 SmartClean/AppMigrate 同款原子+轮询模式）
- `RunScan(ScanState&)`：展开 `%LOCALAPPDATA%`，保留存在的目录，每目标一个 `std::jthread` 递归求大小（跳过 reparse point，模式同 `SmartClean::ScanAll`，`windirstat/SmartClean.cpp:605`）
- `RunClean(...)`：逐文件 `DeleteFileW`（属性重试、sharing-violation→`MOVEFILE_DELAY_UNTIL_REBOOT` 兜底，复用 `SmartClean::DeleteOne` 的逻辑与 `IsDeleteBlocked` 门，`windirstat/SmartClean.cpp:505,692`）→ 文件后自底向上 `RemoveDirectoryW` 清空壳目录（同 `RemoveEmptyParents`，`SmartClean.cpp:546`）
- `IsAppRunning()`：`CreateToolhelp32Snapshot` 检测 `JianyingPro.exe`，供状态栏提示"剪映正在运行，部分文件可能被占用"

## 验证

1. `build.cmd` 编译通过（PreBuildEvent 重新生成语言资源）
2. 启动 DiskSeek，工具栏出现新按钮，悬停提示"剪映缓存清理"
3. 打开对话框自动扫描：列表显示本机 Log(约6.4GB)/CEF 等目标及大小，类型列正确
4. 执行清理：确认框 → 进度 → 摘要；事后检查 `Log` 内容清空、`Projects`/`Presets`/`Config` 完好无损
5. 剪映重启后正常打开、草稿完整
